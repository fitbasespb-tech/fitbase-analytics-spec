1. Цель этапа

За 1 неделю собрать в Yandex DataLens первый рабочий дашборд по каналам РФ:

  • от трат / охватов / кликов,
  • до воронки Лид → MQL → SQL → Продажа по данным AmoCRM.

Гео этого этапа: только РФ.
Каналы в фокусе: Яндекс.Директ, VK Ads, а также агрегированные каналы (SEO, SMM, Direct, Seeding и т.п.).

2. Источники и данные (MVP)

2.1. AmoCRM (обязательно)

Выгрузить в DWH (ClickHouse) таблицу по РФ:

Таблица leads_rf:

  • lead_id — ID сделки
  • created_at — дата создания
  • closed_at — дата закрытия
  • pipeline_id — ID воронки (понадобится позже, сейчас можно не детализировать)
  • status — текущая стадия
  • deal_value — сумма сделки (поле «Бюджет»), ₽
  • lead_type — Lead / MQL / SQL (из поля «Тип заявки»)
  • is_won — флаг «Оплата пришла»
  • country — RF / KZ / UZ
  • utm_source, utm_medium, utm_campaign, utm_content, utm_term

Фильтр: country = 'RF'.

Из этой таблицы на этапе 1 нам нужны агрегаты по РФ:

  • Leads — все сделки
  • MQL — сделки с lead_type = 'MQL'
  • SQL — сделки с lead_type = 'SQL'
  • Sales (Won) — сделки с is_won = true
  • Revenue — сумма deal_value по is_won = true

2.2. Рекламные кабинеты РФ

Таблица ad_costs_rf (ежедневная, РФ):

  • date
  • channel — нормализованный: yandex, vk, а также агрегированные бесплатные каналы
  • campaign_id
  • campaign_name
  • impressions
  • clicks
  • spend (₽)

Заполнение:

  • обязательно: Яндекс.Директ (РФ)
  • обязательно: VK Ads (РФ)
  • агрегировано из Метрики (без ручного ввода):
  • Прямые переходы (прямой трафик)
  • SEO (поисковая органика)
  • SMM (органика из соцсетей)
  • Email и SMS (если помечены UTM)
  • Звонки (если есть отдельный источник/метка)
  • Переходы в мессенджеры (как источник трафика, не путать с самими группами/сообществами)

На этапе 1 посевы (seeding) не подключаем, т.к. сейчас для них нужен ручной ввод.

На этапе 1 по агрегированным каналам допустимо не иметь детальных campaign_id — достаточно уровня «канал / день».

2.2.1. Полный список каналов на этапе 1

Платные каналы (кабинеты):

  • Яндекс.Директ (поиск, РСЯ и др.)
  • VK Реклама (VK Ads)

Бесплатные / условно бесплатные каналы (из Метрики и UTM):

  • Прямые переходы (direct / type‑in)
  • SEO (поисковая органика: Яндекс / Google)
  • SMM (органика из соцсетей: VK, Telegram‑канал, Instagram* и др.)
  • Email‑рассылки
  • SMS‑рассылки
  • Звонки (если есть отдельный источник или UTM‑метка)
  • Переходы в мессенджеры (переход по ссылке в WhatsApp / Telegram / др.; именно как источник трафика, не группы/сообщества)

2.3. Яндекс.Метрика (РФ, fitbase.io)

Таблица web_rf:

  • date
  • utm_source, utm_medium, utm_campaign
  • users — уникальные пользователи (посетители)

Используется для оценки «охвата (посетителей)» по каналам и расчёта CR Посетители → Лиды.

2.4. Справочник каналов

Таблица dim_channel:

  • utm_source, utm_medium
  • channel — нормализованное имя канала, например:
  • платные: Yandex, VK
  • бесплатные: Прямые, SEO, SMM, Email, SMS, Звонки, Мессенджеры

На этапе 1 важно жёстко зафиксировать правила маппинга, чтобы все источники (AmoCRM, Метрика, расходы) давали один и тот же channel.

3. Логика соединения данных

Цель: получить по каждому каналу РФ связку расходы → трафик → лиды/MQL/SQL/продажи.

  1. Канал у лида (по UTM, если есть):
  2. по utm_source / utm_medium / utm_campaign из leads_rf
  3. через dim_channel → нормализованный channel
  4. Канал у расходов:
  5. ad_costs_rf.channel → тот же справочник dim_channel (или идентичные значения)
  6. Канал у посетителей:
  7. web_rf.utm_source / utm_medium / utm_campaign → dim_channel.channel

На первом этапе допускается приближённый матчинг кампаний (по названию / части строки), главное — корректное разнесение по каналам РФ.

3.1. Матчинг лидов без UTM

UTM‑метки не всегда есть (особенно в SEO и части органических каналов). Для таких случаев закладывается дополнительная логика:

  1. SEO (поисковая органика)
  2. В Метрике источник/тип: yandex / organic, google / organic → канал SEO.

  3. Лиды в AmoCRM без UTM попадают в SEO, если:

    • точка входа (страница/лендинг) относится к списку SEO‑страниц (блог, посадки из поиска), или
    • в CRM стоит источник «Сайт / Поисковик» (если такое поле/тег используется).

  4. Прямые переходы

  5. В Метрике источник/тип: direct / (none) → канал Прямые.

  6. Лиды без UTM и без явных признаков платных/SEO‑источников попадают в канал «Прямые».

  7. SMM (органика соцсетей)

  8. В Метрике источники: vk.com, t.me, instagram.com и др. при отсутствии платных UTM → канал SMM.

  9. Лиды без UTM, пришедшие с форм/чатов на соцсетях, также относятся к SMM (по URL источника или полю «Источник» в CRM).

  10. Email, SMS, мессенджеры, звонки

  11. Если есть UTM‑метки → обычный UTM‑матчинг.
  12. Если UTM нет, но:
    • лид создан из конкретного интеграционного источника (email‑сервис, SMS‑шлюз, бот, телефония), или
    • в CRM стоит соответствующий тег/источник («Email‑рассылка», «SMS», «WhatsApp», «Звонок»),
  13. то такой лид относится к каналу Email / SMS / Мессенджеры / Звонки соответственно.

Важно: для всех правил выше нужно явно задокументировать в коде ETL и справочнике dim_channel, какие значения источников/меток относятся к какому каналу — чтобы матчинг был воспроизводим и прозрачен.

4. Дашборд «Channel Performance RF» (первая версия)

4.1. Фильтры

  • Период (даты начала/конца, по умолчанию — текущий месяц)
  • Канал (мультивыбор)
  • Гео = РФ (жёстко зашито в источниках / фильтрах)

4.2. Верхняя панель KPI

Карточки (агрегат по выбранным фильтрам):

  • Расходы, ₽ — суммарные расходы (Spend)
  • Лиды — количество лидов (Leads)
  • MQL — количество MQL
  • SQL — количество SQL
  • Продажи — количество оплаченных сделок (Sales / Won)
  • Выручка, ₽ — сумма deal_value по Won (Revenue)
  • CAC, ₽ — Расходы / Продажи (Spend / Sales)

При наличии времени можно добавить подпись vs предыдущий период для пары ключевых метрик.

4.3. Основная таблица по каналам (с возможностью расширения)

Строка = канал РФ (Яндекс, VK, SEO, SMM, Прямые, Email, SMS, Звонки, Мессенджеры и т.д.).

Колонки (подписи — по‑русски, в скобках — техническое имя поля при необходимости):

  • Канал (channel) — название канала
  • Расходы, ₽ (spend)
  • Показы (impressions) — там, где есть: Яндекс, VK
  • Клики (clicks)
  • CTR — Clicks / Impressions
  • CPC, ₽ — Spend / Clicks
  • Посетители (users) — уникальные пользователи из Метрики
  • Лиды (leads) — лиды в AmoCRM
  • MQL — MQL
  • SQL — SQL
  • Продажи (sales_won) — оплаченные сделки
  • Выручка всего, ₽ (revenue_total)
  • Выручка с лидов текущего месяца, ₽ (revenue_current_cohort)
  • Выручка с лидов прошлых месяцев, ₽ (revenue_past_cohorts)
  • Доля выручки из прошлых месяцев, % (revenue_past_share)
  • CPL, ₽ — Spend / Leads
  • CPA MQL, ₽ — Spend / MQL
  • CPA SQL, ₽ — Spend / SQL
  • CAC, ₽ — Spend / Sales
  • ROAS — Revenue_total / Spend

Требование к структуре:
Сразу проектировать таблицу как иерархическую (раскрывающуюся) в DataLens:

  • Уровень 1 — канал (channel)
  • Уровень 2 — кампания (campaign, кампании внутри канала)

Детализация до креативов (уровень 3) на этом этапе не нужна, но структура должна позволять добавить её на следующем этапе без переделки схемы.

4.4. Визуальный верхнеуровневый блок

Помимо таблицы, на том же дашборде:

  • Столбчатая диаграмма 1 — выручка по каналам (ТОП‑каналы по выручке, можно показывать stacked: текущий месяц / прошлые месяцы)
  • Столбчатая диаграмма 2 — CAC по каналам (сортировка от лучшего к худшему)
  • Линейный график — динамика лидов и продаж по дням (при возможности — добавить MQL и SQL)

4.5. Разделение выручки по когортам лидов

Чтобы честно видеть вклад «длинного хвоста» (лидов из прошлых месяцев), в модель и дашборд закладывается раздельный учёт:

  • Месяц лида (lead_month) — месяц по дате создания лида (created_at).
  • Месяц оплаты (deal_month) — месяц по дате оплаты (closed_at с is_won = true).

В витрине для текущего выбранного периода считаются:

  • revenue_current_cohort — выручка в выбранном периоде только от лидов с lead_month = выбранный_месяц.
  • revenue_past_cohorts — выручка в выбранном периоде от лидов с lead_month < выбранный_месяц.
  • revenue_total = revenue_current_cohort + revenue_past_cohorts.

Это позволяет по каждому каналу видеть:

  • сколько денег даёт текущий маркетинг (лиды этого месяца),
  • сколько доходит «хвостом» от прошлых месяцев,
  • и долю выручки, приходящую из прошлых когорт.

Отдельная сводка по аналогии с текущей Google‑таблицей (лиды/оплаты/доход с лидов месяца и с «старых» когорт) может быть оформлена как дополнительный таб DataLens или отдельный блок в дашборде «Каналы».

5. Приоритеты и ограничения

  • Срок этапа: 1 неделя.
  • Гео: только РФ.
  • Каналы (обязательно): Яндекс.Директ, VK Ads.
  • Каналы (агрегировано, по возможности): SEO, SMM, Direct, Seeding и др.
  • Статусы лида: с первого этапа в дашборд должны попадать минимум:
  • Лиды (все сделки)
  • MQL
  • SQL
  • Продажи (Sales / Won)
  • Разбивка по стадиям воронки и по воронкам (Теплые, Вебинары) — не входит в этап 1, будет реализована на следующих этапах.
